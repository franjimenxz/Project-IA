## Resultado

`RunInvestigationQuery.get(TenantContext, UUID) -> RunInvestigation` reconstruye un run tenant-scoped desde tablas existentes (sin migraciones ni ALTER de owners):

- `RunSummary`: config version, skill, workflow type, MCP server, status, tokens, latencia UTC.
- `ConversationSummary`: ids, status, trigger message id/direction/content_type. Sin body ni `external_user_ref`.
- Retrievals, tools y retries desde `workflow_transition` (payload sanitizado; se descartan chunk/prompt/arguments).
- Workflow, handoff y jobs por joins tenant-scoped. Handoff no expone `patient_reference`, notes ni collected fields.
- Timeline ordenada por timestamp UTC (run, retrieval, tool, retry, transition, job, handoff).
- Paginación cursor de tools y audit events.
- Missing y cross-tenant levantan el mismo `RunNotFound` (`code=not_found`, `Resource not found`).
- Consulta autorizada escribe `run_investigation_queried` en `audit_event`.

No se modificó `redaction.py` ni la propagación/exporter de T01. Se reutilizan `redact`, `sanitize_summary`, `sanitize_payload` y `sanitize_text`.

## Decisiones

- Tools/retrievals se reconstruyen desde `workflow_transition` (no hay tabla `tool_execution`; no se alteran owners).
- Jobs y audit events se acotan a la ventana `[started_at, finished_at]` del run además del tenant/correlation, para no mezclar runs del mismo tenant.
- `trace_url` queda `None` (no hay backend de traces configurado; no se inventa URL).

## Riesgos residuales

El schema actual de `audit_event` no tiene `run_id`; la ventana temporal es una aproximación. P07-T03 debe aplicar RBAC en HTTP y reutilizar este query sin bypassear tenant scope.

**Estado:** in_review

**Entorno:** local · Python 3.13.12 · PostgreSQL `ia_mcp_p02_t03`

## Resultado

`TenantOnboardingService.preflight(TenantContext, content_hash=T01)` ejecuta los checks del TDD como **puertos**, persiste un `PreflightReport` inmutable (hash de tenant + content/config + outcomes) y actualiza `tenant_onboarding_state.package_content_hash`. `activate(admin, report_hash)` exige un reporte passing del **mismo** content/config hash: H1 no activa H2; un check fallido no activa; no hay parámetro de waiver. La activación es transaccional (tenant `active` + `active_config_version` + channel/integration `active` + audit `activate` con hashes redactados). Replay de activate no duplica audit ni mappings. `disable` reutiliza los guards de T02 (JobStore fail-closed, mappings disabled).

HTTP: `POST /v1/admin/tenants/{slug}/preflight` y `/activate` construyen el admin **solo** con `admin_context_for` (mismo factory que T02). El body de activate es únicamente `report_hash` (`extra=forbid`); no se acepta un `TenantAdminContext` ajeno. `tenant_admin` de B no activa C (403/404); `platform_admin` sí. Knowledge unpublished falla cerrado por puerto (T04 no se implementó). `create_onboarding_router` no se cableó en `create_app` (E2E no lo necesita).

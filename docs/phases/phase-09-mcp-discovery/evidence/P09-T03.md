# Evidencia P09-T03 — Generic MCP SSE client + discovery

**Estado:** in_review  
**Implementación:** `implementation/P09-T03-mcp-client`  
**Rojo observado:** `ModuleNotFoundError: No module named 'ia_mcp.mcp.discovery'` y `No module named 'ia_mcp.mcp.client'`  
**Calidad:** `auth_reference` se guarda en `McpEndpoint` y no viaja en headers, logs ni `safe_message`.

## Resultado

`SseMcpClient` abre `GET /sse`, lee el evento `endpoint` y envía JSON-RPC por `POST /messages/?session_id=`. `list_tools` devuelve `ToolCatalog`; `call_tool` devuelve `ToolResult`. Las sesiones se aislan por `tenant_id` + `server_id` + endpoint. No hay ramas por institución, no se inventa API médica REST y no se envían tokens.

## Decisiones y desviaciones

`McpEndpoint` vive en `discovery.py` (no se importa `McpTarget` desde `executor.py`) para no acoplar discovery al executor de P09-T04 ni crear un ciclo. No se escribió ADR-005. `executor.py` y `registry.py` no se modificaron.

## Riesgos residuales

El handshake usa `protocolVersion` `2024-11-05`. Un servidor FastMCP que exija otra versión puede fallar en el e2e live. Host allowlist queda en P09-T04.
